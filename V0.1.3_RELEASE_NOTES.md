# ClipPulse v0.1.3 Beta

This beta fixes recurring ClipPulse MCP entries and confusing folder-permission failures when connecting Codex or Claude Code.

## Highlights

- Reuses and updates the existing ClipPulse-managed MCP server entry instead of adding a new numbered entry each time setup runs.
- Consolidates duplicate entries previously created by ClipPulse while preserving unrelated client servers and writing a dated configuration backup first.
- Loads previously granted folders into Agent Setup, so users can review, add, or remove media, music, project, and export roots together.
- Provides separate folder pickers for source media/music and a permanent project/export location. Chat-specific output folders still need an explicit grant.
- Explains denied paths and how to correct them without broadening filesystem permissions.

## Verification and limitations

- Windows x64 build, automated tests, local CLI/MCP/media/export smoke test, and production dependency audit were run for this beta candidate.
- Windows installer packaging and install/start smoke-test results are recorded in the release checklist and CI artifacts.
- Linux x64, macOS arm64, and macOS Intel must pass the tag-triggered release workflow before this draft is published. They have not been tested on this local Windows machine.
- A fresh Codex editing session was not used to make a full montage during this verification. Claude Code was unavailable locally.
- ClipPulse remains a beta. FFmpeg and FFprobe are separate user-installed dependencies; unsigned packages may show operating-system security warnings.
